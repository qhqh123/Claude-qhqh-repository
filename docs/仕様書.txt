【仕様項目 No.00：実装AIへの指示（最初に必ず読むこと）】
==================================================

■ 一度に全部作らない
この仕様は大きい。全機能を一度に浅く実装すると、動くが面白くないゲームになる。
以下のフェーズ順に実装し、各フェーズが「遊べる状態」になってから次へ進むこと。

フェーズ1（コア。これだけで作品として成立させる）
・牛のみ
・見下ろし2Dのスクロールマップ（事務所、牛の放牧地・畜舎、開拓前の丘と荒れ地、案内看板、町ウィンドウ）
・個体詳細画面（基本・家系図・履歴タブ、バッジのツールチップ）
・個体管理、季節ターン、成長
・交配（牧場内の雄、人工授精）、妊娠、出産
・去勢（全術式、直接対応／外部委託、文章イベント、既読スキップ）
・肥育と食肉出荷、出荷画面
・帳簿（No.18）、借入金と年次決算（No.02）
・セーブ／ロード、フレーバーテキストJSON

フェーズ2：搾乳施設と泌乳サイクル、畑と牧草
フェーズ3：馬（農耕馬、競走馬、外部種牡馬、レース、当て馬）
フェーズ4：個体関係の詳細表示、厩務員の性格相性、開発者モード
後のフェーズの候補（未確定）：牛の品評会（共進会）。牛の育種成果を競う年1回の催し。

※開発者モードのうち、文章IDの表示とコピーだけはフェーズ1で最小限実装する（文章イベントの確認用）。

■ 優先順位
数値計算の精密さよりも、次の3つを優先する。この3つが弱いと作品が成立しない。
1. かわいい牧場ゲームとしての手触り（No.19）
2. 文章イベントの表示の仕組み（No.15。本文は後から差し込む）
3. 日誌（文章）と帳簿（数値）の対比（No.01、No.18）

■ 文章イベントの本文は書かない
去勢・繁殖・出荷の文章イベントの本文は、実装AIが書かない。創作も補完もしない。
本文はゲーム完成後に、別管理の文章データでJSONを差し替えて入れる。
実装AIは付録Aの文章IDでダミーJSONを作り、次を完成させること。
・イベントの表示順、条件分岐、ランダム選択、確率表示
・ノベル形式のテキストウィンドウ、クリック送り、既読スキップ、既読管理
・JSONの差し替えと再読み込み、開発者モードでのID表示
日常イベントや厩務員の短い台詞もダミーでよい。

■ 仕様書の文章を画面に出さない（最重要）
この仕様書の説明文、理由、計算式、注記は、実装のための情報であって、画面の文字列ではない。
画面に出してよい文字列は、次の3種類だけとする。
1. 文章JSON（No.21）の本文
2. 仕様書の中で「表示：」と明記した文字列（そのまま一字一句使う）
3. ボタン名、項目名、ステータス名、数値、単位
次のような説明口調の文を、UI、ポップアップ、ツールチップ、通知、ヘルプのどこにも出さない。
・「〜な仕様です」「〜という仕組みです」「〜となっています」
・「〜のため、〜します」「〜できます（説明として）」
・仕様書の文をそのまま、または言い換えて表示したもの
ツールチップも「表示：」で指定した文だけを使う。指定がない項目にはツールチップを付けない。
【設計意図・非表示】と書いた段落は、実装AIへの説明であり、絶対に画面に出さない。
迷ったら表示しない。

■ 仕様を単純に読むと誤解しやすい点（必ず守ること）
・牧場は「恵まれていない状態」から始まる。初期の家畜の遺伝能力は低く、
  外部の種雄（精液ストロー・種牡馬）との交配を重ねて改良していくのが基本の体験である。
  初期個体や家畜市場に高ランク個体を並べてはいけない（付録C）。
・UIに説明文を常時表示しない。仕組みの説明は、マウスオーバー（スマホではタップ）で
  出るツールチップで行う。画面上の固定の注記・凡例・説明行は置かない。
・マップは広く、歩いて回る価値があるものにする。画面に収まる小さなマップにしない（No.17）。
・家畜は所属する放牧地の柵の外に出ない。

■ 作品意図はこの仕様書の中だけに置く
ゲーム内のどのテキスト（UI、通知、文章イベント、ヘルプ、実績名）にも、
倫理的なメッセージ、作品意図の説明、プレイヤーへの評価を書かない。
「考えさせられる」「命の重さ」「残酷」「かわいそう」などの語をゲーム内で使わない。
UIは徹底して、明るくかわいい普通の牧場ゲームとして作る。

【仕様項目 No.01：作品の主題と表現原則】
==================================================
【設計意図・非表示】この項目全体が実装AIへの説明である。画面に出さない。

本作は、かわいらしい見下ろし2Dの牧場経営ゲームである。
プレイヤーは牛や馬を育て、名前を付け、世話をし、
繁殖、搾乳、農耕、競走、食肉出荷を通じて経営する。

本作の中心的な題材は、一般的な牧場ゲームで省略されがちな、
現実の畜産における動物の身体への介入、特に生殖の管理である。
・雄牛・牡馬の去勢
・人工授精や外部種雄による、経営判断にもとづく交配
・乳牛の泌乳には出産が必要であること

■ 二層記述の原則（本作の中核）
同じ出来事を、必ず2つの書き方で記録する。

1. 日誌（文章）
   去勢や繁殖の場面を、ノベルゲーム形式の文章で詳しく描く。
   処置の具体的な内容、生殖器官の構造と機能、失われる繁殖能力、
   動物の反応、厩務員の主観を省略せずに書く。

2. 帳簿（数値）
   同じ出来事を、費用・作業時間・成長予測・格付予測の1〜3行で記録する。
   帳簿には感情や描写を一切含めない。

経営判断に必要な情報はすべて帳簿とUIで得られる。日誌を読まなくても、
スキップしても、経営結果は1円も変わらない。
日誌を読んだかどうかはどこにも評価・表示しない。

■ 描写の範囲
・血液、内臓、処置の様子を写実的な画像で描かない。
・視覚表現はよくある牧場ゲームの範囲に保ち、身体的な現実は文章で伝える。
・文章の細密さは去勢と繁殖の場面に集中させる。日常イベントや経営イベントは
  短く軽く書く。この密度の偏り自体が演出である。他の場面を同じ密度にしない。

■ 結論を与えない
・ゲームは利益を得る行為を否定しない。
・動物への愛着や終生飼育を特別に称賛しない。
・カルマ値、善悪判定、倫理的な分岐、ヴィーガンへの言及を設けない。
・普段は省略されている過程を具体的に示し、その過程を経た商品が普通に流通し、
  牧場経営が普通に成立していることを、並べて見せるだけにする。

家畜は名前、性格、なつき度、個体関係を持つ。
一方、食肉や牛乳の販売では、重量、品質、数量、価格などの商品情報だけを扱う。
出荷を境に、個体は「名前のある家畜」から「個体識別番号のある商品」に切り替わる（No.18）。

【仕様項目 No.02：季節ターン・コアループ・目標】
==================================================

■ 季節ターン
1ターンを1季節（約3か月）とする。春・夏・秋・冬の4ターンで1年。
現実の生育・繁殖期間を参考にしつつ、ゲームとして圧縮する。

・交配から2〜3ターンで出産。
・出生した雄は、出生ターンから去勢判断期に入る（時期区分はNo.14）。
・出生から4〜8ターンで最初の出荷判断期を迎える。
・成長、繁殖、泌乳、肥育、加齢はターン経過で自動処理する。

■ 1ターンの流れ（コアループ）
1. ターン開始：季節の切り替え演出（No.19）。前ターンの処置の経過日誌が届く。
2. 通知を確認：去勢判断期、交配可能、出産、出荷適期など。
3. 経営判断：交配、去勢、出荷、配置、購入、施設拡張。
4. 任意のお世話：ブラッシング、ふれあい、運動。
5. ターン終了ボタン。
6. 季節の収支サマリー（帳簿のその季節分）を表示。
7. 冬のターン終了時のみ、年次決算と借入返済を行う。

■ 通知
重要な成長段階に達すると、画面に通知ポップアップを表示する。
・去勢を検討できる時期に達した
・雌が交配可能になった／発情した
・妊娠個体が出産した
・乳牛が搾乳可能になった／泌乳が低下した
・家畜が出荷適期に達した
・家畜が死亡した

通知はその場で対応せず無視・保留できる。後から事務所で見直せる。
通知はかわいいデザインで統一する（去勢判断期の通知も、他の通知と同じ見た目にする）。

■ 目標と経営の圧力
【設計意図・非表示】目的のない経営ゲームは単調になる。また、経営の圧力がないと、プレイヤーは
すべての個体を手元に残せてしまい、去勢や出荷の判断に重みが生まれない。
そのため、次の圧力を設ける。

・開始時に借入金がある（初期値は付録Cの定数一覧）。
・毎年冬の年次決算で、一定額を返済する。
・返済できない場合は利息が加算されて翌年に繰り越す。ゲームオーバーにはしない。
・飼料の自動購入などで資金がマイナスになった場合、ターン終了時に不足分を借入金へ自動で加算し、
  帳簿に1行記録する（例：「借入金 振替　¥420,000」）。ゲームオーバーにはしない。
・借入完済後は自由経営になる。

■ 経営記録（実績）
事務所に「牧場の記録」として、経営上の節目を記録する。
例：初出荷、年間売上100万円・500万円・1000万円、初めての肉質A評価、
初めてのSランク個体作出、借入完済、飼育頭数20頭・50頭。
実績名はすべて経営用語だけで書く。去勢や出荷頭数を「達成」として祝う実績は作らない。

【仕様項目 No.03：牧場の経営方針・収益構造】
==================================================

牧場の収益源は、安定型と変動型に分かれる。

安定型収益：
・畑からの作物収入
・乳牛の搾乳による乳収入
・農耕馬による畑効率の補助

変動型収益：
・牛馬の食肉出荷
・競走馬のレース賞金
・家畜や産子の売却

畑と搾乳施設は、牧場の基礎的な安定収入源とする。
これにより、繁殖や競馬で失敗しても経営が完全には破綻しにくい構造にする。
畑スロットには馬、搾乳スロットには牛を配置できる。配置中は収益が生まれる。
シンプルな区画・スロット制とし、細かな作業よりも規模拡張と効率管理を中心に扱う。

生まれすぎた仔牛、育った牛、能力が低下した個体の食肉出荷は、
まとまった収入を得る手段とする。肉牛・乳牛という種類分けは設けない。

競走馬は高リスク高リターンの収入源とし、安定収入源にはしない。

プレイヤーは自然に、安定経営、育種と出荷、競馬、愛玩的な飼育のいずれかを
重視することになる。これらの選択にカルマ値や善悪判定は設けない。

■ 維持費
牧場の主な維持費は、飼料、施設維持費、そして保有枠を圧迫すること自体とする。

牧草・飼料：
・家畜は飼料を必要とする。
・牧草地の規模に応じて飼料を自給できる。
・不足分は市場から自動購入する。
・飼料費は季節で変わる。夏は放牧で安く、冬は高い（付録C）。フェーズ1で季節が経営に効く要素とする。
・畑は収益施設、牧草地は飼料費削減施設として区別する。

NPC厩務員：
・NPC厩務員が給餌、清掃、基本的な世話を自動で行う。
  プレイヤーが世話をしなくても、健康を害したり飢えたりはしない。
・プレイヤー自身によるブラッシングやおやつなどのお世話は、
  ステータスを高めるための任意の追加行動とする。

施設維持費：
・放牧地、畜舎、畑、搾乳施設に維持費が発生する。
・施設やスロットの増設にはまとまった資金が必要。

保有枠：
・飼育枠は家畜の最大頭数を決める。
・労働枠は生産に配置できる家畜数を決める。
・働いていない家畜にも維持費が発生する。
・保有枠はゲーム内通貨で拡張する。厩務員の追加、放牧地の拡張、人件費などを
  一括してまとめた「保有枠拡張」として扱う。

【仕様項目 No.04：畑の生産と農耕馬】（フェーズ2・3）
==================================================

畑は区画A、B、C…のスロット制で管理する。
各区画は「商業作物」または「牧草」の用途を選べる。

商業作物：毎ターン、区画の生産力に応じた現金収入を得る。作物の種類は細分化しない。
牧草：毎ターン、区画の生産力に応じた飼料を生産する。家畜の維持に優先して使用し、
不足分は自動購入、余剰分は安価で自動売却する。

農耕馬：
・各畑スロットに農耕馬を1頭配置できる。
・配置しなくても牧草の基本生産は行われる（0.5倍）。
・農耕馬のスタミナとコンディションに応じて生産量が増える。
・任意のお世話による当代能力の成長も生産に反映する。

畑の生育期間や収穫時期は個別管理せず、毎ターンの平均生産量として表現する。

農耕能力と生産倍率：
| 農耕馬の能力 | 商業作物 | 牧草 |
| 未配置       | 配置不可 | 0.5倍 |
| 平凡         | 1.0倍    | 1.0倍 |
| やや優秀     | 1.5倍    | 1.2倍 |
| 優秀         | 2.5倍    | 1.5倍 |
| 最高水準     | 4.0倍    | 2.0倍 |

【設計意図・非表示】高い能力の馬は商業作物に、低い能力の馬や空きスロットは牧草に使うと有利になるバランスにする。この助言を画面に出さない。

表示例：
畑スロットA：商業作物（カブ・小麦など）／担当馬：ハヤテ／季節収益：3万円
畑スロットB：牧草／担当馬：ポニー（1.5倍）／季節生産：飼料15単位
畑スロットC：牧草／担当馬：なし（0.5倍）／季節生産：飼料5単位

【仕様項目 No.05：家畜の個体管理】
==================================================

家畜は頭数ではなく、すべて独立した個体データとして管理する。
対象動物は牛と馬（フェーズ1は牛のみ）。

牛は乳用適性と肉用適性、馬は競走適性と農耕適性を持つ。
厳密な品種分類ではなく、個体の適性差を重視する。

各個体は以下の情報を持つ。
・固有ID（内部用）
・個体識別番号（10桁の数字。出生時または購入時に発行。出荷画面と帳簿に表示）
・名前（プレイヤーが変更可能）
・動物種、性別、年齢（ターン数）
・状態：飼育中、出荷済み、売却済み、死亡
・健康、幸福度、ストレス
・性格と好きな活動
・プレイヤー、厩務員ガール、厩務員ボーイへのなつき度
・他の家畜との関係性
・遺伝特性と生産適性
・父、母、子の情報
・繁殖状態、妊娠、去勢の有無と去勢時期・術式
・生産履歴、繁殖履歴、処置履歴

出荷や死亡によって飼育対象から外れた後も、個体の履歴は牧場の記録として保持し、
事務所で閲覧できる（No.18 の個体アーカイブ）。

■ 個体詳細画面のタブ
個体詳細画面はタブで切り替える。
・基本：立ち絵、名前、性別、年齢、健康、幸福度、ストレス、遺伝バッジ、繁殖状態
・関係：個体関係（No.09）
・家系図：下記
・履歴：生産・繁殖・処置の履歴、過去の日誌

■ 家系図タブ
・3世代の血統表を表示する：本人、父・母、父父・父母・母父・母母。
・各祖先に、体格バッジと主要な特性バッジを小さく表示する。
・外部種雄（精液ストロー、外部種牡馬）は「外部」と区分を表示する。
  外部種雄の祖先は、町のカタログに載っている範囲の情報だけを持つ。
・産子・後代の一覧：その個体が産んだ子、または父として残した子を一覧表示する。
・家系図・後代一覧に出てくる個体のうち、牧場で飼育中の個体は名前をクリックすると
  その個体詳細へジャンプする。出荷・死亡した個体は個体アーカイブへジャンプする。
・詳細画面の上部に「戻る」ボタンを置き、ジャンプ元に戻れるようにする。

【仕様項目 No.06：遺伝・特性バッジ】
==================================================

遺伝特性は、確定で遺伝する体格2枠と、遺伝するかもしれない自由特性4枠で管理する。

体格：
・【伸び/骨格】【深み/肉付き】
・父母の同種バッジを合成する。同ランクなら1段階上昇、異なるランクなら高い方を採用。
・上限はS。

自由特性：
・父から1〜3枠、残りを母から抽選し、最大4枠を継承する。
・同種バッジが重なった場合は合成する。
・父母のバッジが乏しい場合や合成により、4枠未満になることもある。

【設計意図・非表示】遺伝ルールが単純で、同ランクの合成で確実に上がるのは意図した仕様である。
本作の育種は「微妙な配合でも牧場で仲のよい個体同士を交配させるか、それを無視して雄は去勢し、
雌には外部の高級精液（馬なら外部種牡馬）を付けるか」という選択のゲームである。
外部種雄のカタログを適切に回せば（ガチャ）改良は進む。その代わり、カタログからはSが手に入らず、
高ランクほど【気性難】【虚弱体質】などのデメリット特性を同時に引きやすいように調整する。
遺伝ルールを複雑にしない。近親交配の補正は実装しない。

ランク：0＝特記なし、1＝C、2＝B、3＝A、4＝A+、5＝S
バッジなしは補正なし（内部数値0）。

特性の例：
・牛：【乳量】【乳質】
・馬：【スピード】【スタミナ】
・共通：【肉質】【成長速度】【愛嬌】
・デメリット：【気性難】【虚弱体質】ほか（馬はNo.13）
デメリット特性も同じく遺伝し、重なるとランクが上がりうる。

■ バッジの説明はツールチップで行う
特性欄に「自由特性バッジ（最大4枠・灰色は性別または去勢により非発現）」のような
説明文を常時表示してはいけない。バッジだけを並べる。
バッジにマウスオーバー（スマホではタップ）すると、マウスに追随する丸い吹き出しで説明を出す。
吹き出しの文字列（バッジごとに用意する。以下は見本）：
・表示：「気性難 B　トラブルが起きやすい　就労・出走不能 C10% / B20% / A30% / A+40% / S50%」
・表示：「乳量 A　搾乳量が多い」
・灰色のバッジでは、2行目に理由だけを足す。表示：「メスのため非発現」／「オスのため非発現」／「去勢により非発現」
吹き出しは短い体言止めにする。「〜な特性です」「〜という仕様です」とは書かない。

■ グレーアウト表示
発現しない特性はグレーアウトして表示するが、遺伝の対象には含める。
・雌の【気性難】：雌では発現しないが、息子に遺伝すれば発現しうる。
・雄の【乳量】【乳質】：自身は乳を出さないが、娘に遺伝する。
・去勢した雄の【気性難】：去勢によって発現しなくなりグレーアウトする。

表示例：
ハナコ♀　牛　2歳3か月
体格【伸び/骨格A】【深み/肉付きB】
特性【乳量A】【成長速度C】【虚弱体質B】【気性難】（グレーアウト）

【仕様項目 No.07：成長・加齢・生産寿命】
==================================================

牛と馬は出生から成長、成熟、老齢までのライフサイクルを持つ。
・幼齢期は繁殖や本格的な生産ができない。
・成長に伴って体格と生殖能力が発達する（成熟ターンは付録C）。
・成熟後は適性に応じた生産活動が可能になる。
・一定の年齢以降、生産効率が低下する。
・疾病や健康状態も生産能力に影響する。

生産効率が落ちた個体は、食肉出荷、用途転換、終生飼育を選べる。
終生飼育はコマンドではなく、出荷を選ばないことを指す。
終生飼育に善悪評価は設けない。飼料費、施設容量は引き続き消費する。

事故、病気、加齢による死亡も発生しうる。通知ポップアップで知らせる。
フェーズ1では、死亡は老衰とまれな事故のみとする（確率は付録C）。病気は後のフェーズで定義する。


==================================================
【仕様項目 No.08：幸福度・ストレス・コンディション】
==================================================

幸福度とストレスはそれぞれ0〜100の独立した値とする。
・幸福度：普段の生活やふれあいを反映し、ゆっくり変化する。
・ストレス：去勢、疾病、気性難によるトラブルなどで増加し、
  ターン経過（厩務員の日常管理による自然回復）や任意のお世話で回復する。

同じ放牧地に好きな個体がいると、幸福度に小さなプラス補正。
嫌いな個体がいると、ストレスに小さな負担。母子関係も好意として扱う。
畑・搾乳施設への労働配置は、放牧地での個体関係を変化させない。

幸福度とストレスはコンディションを通じて、生産効率、成長、レースに反映する。

状態の例：
| 幸福度 | ストレス | 状態の例 |
| 高い | 低い | 普段から落ち着いて暮らしている |
| 高い | 高い | 普段はよく世話されているが、最近去勢処置を受けた |
| 低い | 低い | 特別な楽しみは少ないが、大きな負担もない |
| 低い | 高い | 飼育環境が合わず、最近の負担も大きい |

【仕様項目 No.09：家畜同士の親密度】（詳細表示はフェーズ4）
==================================================

親密度は一方向の好意を基本とする。全組み合わせを保存せず、
母子関係、個体ごとの好き嫌い、性格マッチ、繁殖関心を合算して表示する。

■ 性格
【おっとり】【甘えん坊】【活発】【好奇心旺盛】【マイペース】【頑固】の6種。
子の性格：父と同じ25%、母と同じ25%、ランダム50%。
相性のよい性格同士は、相手への好感+1（好き嫌いとは独立して計算）。
性格の数値効果はこの好感補正のみ。行動傾向は文章差分にだけ反映する。

■ 母子関係
出生時に設定。仔→母 +2〜3、母→仔 +1〜3。性格に関係なく発生し、
性格が合えばさらに+1。通常の好き嫌い枠とは別に保持する。

■ 個体ごとの好き嫌い
成熟までに、同じ放牧地の個体から以下を獲得する。
・好きな個体：基本2頭、それぞれ+1〜3
・嫌いな個体：基本1頭、−1
好き嫌いは一方向で、相互とは限らない。成熟後は基本的に固定。

【愛嬌】を持つ個体は、好きな個体が「内部ランクと同じ数」だけ追加される（S なら+5頭）。
【気性難】を持つ個体は、成長中に嫌いな相手が増えやすい。

■ 繁殖関心
成熟した未去勢雄は繁殖関心1〜3を持つ（個体ごとにランダム）。
特定の雌への好意ではなく、同種の成熟雌全員に一律に加算される。
去勢すると繁殖関心は0になる。母子関係、個体への好意、性格相性は変化しない。

■ 表示
表示親密度 ＝ 母子関係 ＋ 好き嫌い ＋ 性格マッチ ＋ 繁殖関心
・個体への好意は♡、繁殖関心は♥で表示する。
・合計が正ならハートと数値、負なら✕と数値。合計0の相手は一覧から省略
  （内訳には残す）。
・繁殖関心だけでハートが付く成熟雌は、一覧から省略して「その他の成熟雌」にまとめる。
・去勢後は♥部分が消え、♡部分だけが残る。

関係値のUIは、恋愛シミュレーションゲームのような明るい見た目にする。
ラベルは 表示：「関係値（推定）」 とする。それ以外の説明は添えない。
内訳の各行は、見本の 表示：「モカと一緒に過ごすことが多いようだ」 のような観察の一文と数値だけにする。
繁殖関心の行は 表示：「♥♥♥ +3」 のみとし、計算方法の説明文を付けない。

表示例（モモ：成熟した未去勢雄牛、繁殖関心3）：

・チョコと性格が合うようだ　チョコへの好感 +1

【仕様項目 No.10：繁殖・交配・出産】
==================================================

成熟した雌雄の牛馬は繁殖可能。
・牛：牧場内の雄との自然交配、または人工授精（精液ストローを町で購入）
・馬：牧場内の雄、または外部種牡馬（馬に人工授精はない）
外部の精液・種牡馬は、能力が高いほど高価。Aランクが基本、A+は高額。
馬のA+種牡馬は【気性難】などのデメリット特性を併せ持つことが多い。
Sランクは自分で作出する必要がある。

■ 家畜市場（セリ）
町の家畜市場では、毎ターン数頭の売り出し個体が入れ替わる。
・売り出し個体の能力は低めに偏らせる。特性は平凡〜C中心、ときどきB。
  A以上の個体は市場に出さない（分布は付録C）。
・【設計意図・非表示】高い能力は、外部種雄との交配で自分の牧場の中に作っていくものとする。
・外部種雄（精液ストロー、外部種牡馬）のカタログはA・A+のみで、Sはない。

■ 受胎
・自然交配：受胎率は付録C。
・人工授精：受胎率は付録C。不受胎の場合、次の発情（翌ターン）まで空胎となる。
・空胎の期間は、帳簿に「空胎」として飼料費とともに記録する。
交配の可否に個体間の好感を要求しない。人工授精と外部種雄は好感に依存しない。

■ 産子の予想
交配相手（牧場内の雄、精液ストロー、外部種牡馬）を選ぶ画面で、産子の予想をバッジで表示する。
・体格：合成ルールによる確定の結果を表示する。
・自由特性：継承しうるバッジ（合成後のランク）を並べる。確率は表示しない。
・見出しは 表示：「産子の予想」 とし、説明文は付けない。

■ 文章演出
・自然交配の文章には個体関係を反映する（仲の良い相手かどうか）。
・人工授精では、雌と仲の良い雄が同じ放牧地にいる場合、厩務員の主観の一文が
  入る場合がある（例：付録A の「breed.ai.staff_*」）。
・関係値は交配の成否・産子の能力に影響しない。

■ 出産
受胎すると2〜3ターン後に出産する。父母の遺伝バッジから産子の特性を決める。
出生時に性別、名前、遺伝特性、個体識別番号を確定し、新しい個体として登録する。
乳牛は出産によって泌乳を開始する（No.11）。馬は搾乳収益を生まない。

【仕様項目 No.11：乳牛の生産】（フェーズ2）
==================================================

■ 搾乳施設
搾乳施設はスロットで管理し、各スロットに乳牛を1頭配置する。
増設には資金が必要。配置はプレイヤーが変更するまで維持される。
妊娠中や泌乳終了後もスロットに残せる（生産量0のまま占有する）。
出産後は配置を維持したまま自動的に搾乳を再開する。

■ 泌乳サイクル
泌乳倍率（出産後の経過ターン）：
1ターン目100%、2ターン目100%、3ターン目75%、4ターン目50%、5ターン目25%、6ターン目以降10%
泌乳4〜5ターン目が再種付けの目安。

■ 妊娠中の搾乳と乾乳
・受胎後も、泌乳倍率に従って搾乳を続ける。
・出産予定の直前1ターンは乾乳期間とし、乳量0とする。

■ 季節補正
春1.3倍、夏1.0倍、秋1.2倍、冬1.1倍。季節は乳質ランクに影響しない。

■ 乳量（1ターンあたりのリットル）
生産乳量 ＝ 基礎乳量 × 深み補正 × 泌乳倍率 × 季節倍率 × 年齢補正 × コンディション補正
基礎乳量：平凡1,200L、C1,500L、B1,800L、A2,100L、A+2,400L、S2,700L
【深み/肉付き】で最大約25%増加する。

■ 乳質
乳質は6段階（平凡、C、B、A、A+、S）の離散評価。
【乳質】の遺伝ランクを基礎とし、乳量が高すぎる場合は成分の希釈でランクが下がる。
・希釈判定：基礎乳量×深み補正（季節・泌乳段階・年齢・コンディションを除く）
  が2,500Lを超えると1段階、3,000Lを超えると2段階下げる。0未満にはならない。
・遺伝バッジは変化しない。スロット画面で遺伝ランクと発現ランク、希釈補正を確認できる。

販売単価：平凡90円/L、C100円/L、B110円/L、A125円/L、A+150円/L、S190円/L
乳収益 ＝ 生産リットル × 発現乳質の単価

■ 生産性低下の通知
乳量が一定以下になったら通知し、以下を促す。
・再種付けを行う／搾乳スロットから外す／現在の配置を維持する
老齢による低下は再出産では解消しない。この場合も通知する。

【仕様項目 No.12：食肉価値と出荷判断】
==================================================

牛と馬は食肉として出荷できる。乳牛、競走馬、農耕馬、繁殖用個体も対象。
食肉の出荷価値は、肉重量、遺伝肉質、成長段階、去勢時期、肥育経過で決まる。

■ 肉重量
・【伸び/骨格】を主要な重量要素、【深み/肉付き】を追加要素とする。
・成長段階、健康、コンディションも反映する。
  ストレスが高いと増体が鈍り、非常に高いと減少し、回復するとまた伸びる。
・出生後は急速に増加し、成熟に近づくほど鈍化する。
・未去勢雄は雄性ホルモンによる増体効果を得て、早期去勢個体より大きく育ちやすい。

■ 肉質
・遺伝バッジ【肉質】を基礎とし、遺伝的素質と実際の食肉評価を区別する。
・高齢の乳牛、未去勢の高齢種牛は、食肉評価に大きな減価がかかる。
・成長と肥育で評価が上がる。
・去勢時期によって柔らかさと脂肪交雑の発達が変わる（簡易な増減補正）。
・バイヤーのフレーバー評価（「サシの入りがいいね」など）は文章のみ。

食肉価格 ＝ 枝肉重量 × 肉質による単価 − 未去勢雄の減価

■ 去勢時期による違い（時期区分はNo.14）
早期去勢：回復負担が小さい（ストレスは次ターンに回復）。柔らかさ・脂肪交雑で有利。最終肉重量はやや小さい。
標準去勢：肉重量と肉質のバランスがよい。肉牛生産の基本ルート。経済的に最も有利になるよう調整する。
晩期去勢：未去勢期間の成長で肉重量が増える。術後の一時的な体重減少が大きい。
高齢去勢：繁殖用の成牛を去勢して再肥育する。体格は維持され、数ターンかけて評価が改善するが、若齢去勢と同じ肉質には戻らない。

■ 未去勢雄の減価
去勢判断期以降、未去勢のまま成長すると減価が蓄積する。
去勢すると蓄積は止まり、それまでの減価は再肥育によって段階的に改善する。

■ 種牛の出荷
役割を終えた雄牛は、次のどちらかを選べる。
・未去勢のまま即出荷：評価は低いが、すぐに売却でき、枠と維持費を解放できる。
・去勢して再肥育：費用と期間を追加で負担し、評価の改善を狙う。

出荷画面と出荷後の扱いはNo.18で定める。

【仕様項目 No.13：競走馬・農耕馬】（フェーズ3）
==================================================

馬の競走能力は【スピード】【スタミナ】で表現する（C〜S）。
安定して勝つにはB〜A以上が必要。

レース：
・短距離：スピード75%、スタミナ25%
・中距離：各50%
・長距離：スピード25%、スタミナ75%
・当代の育成状態とコンディションも反映する。

農耕馬：
・スタミナを農耕適性として使う（No.04）。
・競走馬として育てた個体も農耕に転用できる。

マイナスバッジ（C〜Sで悪影響が強まる）：
・【気性難】：就労・出走不能率を高める（C=10%、S=50%で出走拒否）。
・【虚弱体質】：ストレスによる悪影響を強める。
・【臆病】：レースで能力を発揮しにくくする。
・【気まぐれ】：レース成績のばらつきを増やす。

外部種牡馬：
・競走向け：スピード・スタミナが高いが、マイナスバッジが多い。
・農耕向け：スタミナが高く、マイナスバッジが比較的少ない。

【設計意図・非表示】牛と馬で育種の難易度が異なるのは意図した仕様である。
農耕馬を目指すなら【深み/肉付き】と【スタミナ】を伸ばせばよく、難易度は低い。
競走馬（サラブレッド）を目指す場合は、牛よりも受け継ぎやすいデメリット特性が多く、
邪魔な遺伝要素を避けながら配合する高難度の育種になる。両者のバランスをそろえない。

【競走馬】バッジ（ランクなし）：
・保有するとレース評価点の基礎値+5。
・父母ともに保有なら、子は自由4枠の外で確定継承（特性が5個になりうる）。
・片親のみなら通常の自由枠抽選に混ざる。

レース判定：
・通常レース（G3・G2・G1）と、【競走馬】を持たない馬限定の農耕馬レース。
・評価点 ＝（距離適性 ＋ コンディション補正 ＋ 基礎乱数 ＋ 競走馬補正）× 展開乱数
・競走相手の個体シミュレーションは作らない。グレードごとの入賞ライン・勝利ラインで判定する。
・出走不能の判定は評価点の計算前に行う。

当て馬：
・未去勢の牡馬は「当て馬」として、雌の発情確認に使える（外部種牡馬との交配時）。
・当て馬を使うと受胎率が上がる（付録C）。
・当て馬の場面には文章イベントがある（付録A の「breed.teaser.*」）。

【仕様項目 No.14：去勢システム】
==================================================

雄牛・牡馬は去勢判断期を迎えると通知ポップアップを表示する。
去勢するか、未去勢のまま繁殖用・育成用に残すかを選ぶ。判断期を過ぎても任意に去勢できる。

去勢によって繁殖能力を失い、繁殖関心が0になり、雄性ホルモンに関連する行動と、
食肉としての成長・評価が変化する。

■ 去勢の術式は牛・馬とも四手法（ゴムリング法、去勢鉗子法、観血法、旧来手法）。選択画面は共通で、
  時期に関係なくすべて選べる。牛と馬で異なるのは、時期ごとの推奨術式と成功率だけ。

■ 時期区分と適した術式（牛）
| 時期 | 月齢の目安 | 適した術式 |
| 早期 | 出生ターン | ゴムリング法、去勢鉗子法、観血法 |
| 標準 | 出生後1〜2ターン | 去勢鉗子法、観血法 |
| 晩期 | 出生後3ターン以降 | 観血法 |
| 高齢 | 成熟後 | 観血法 |
旧来手法はどの時期でも処置として成立する（不完全・感染は観血法と同程度）。下記のとおり、ストレスが残りやすい。

■ 時期区分と適した術式（馬）
| 時期 | 月齢の目安 | 適した術式 |
| 早期 | 出生ターン | 観血法、旧来手法 |
| 標準 | 出生後1〜2ターン | 観血法、旧来手法 |
| 晩期 | 出生後3ターン〜成熟前 | 観血法、旧来手法 |
| 高齢 | 成熟後 | 観血法、旧来手法 |
馬の外部委託は術式を選ばず、成功率95%（不完全率は牛の去勢鉗子法の不完全率と同じ値を使う）。

■ 選び間違い
直接対応では、時期に関係なく、すべての術式を選べる。適さない術式を選んでも確認や警告は出さない。
適さない術式を選ぶと、不完全・感染・ストレスの増加が起きやすくなる（数値は付録C）。
・どの術式が適しているかの手がかりは、町の「獣医」から得られる獣医アドバイスの文章だけとする。
  アドバイスは文章JSON（vet.advice.*）で管理し、本文は後から差し込む（付録A）。
・選択ウィンドウには時期名（早期・標準・晩期・高齢）を表示する。適否の印は付けない。
・結果は通常どおり帳簿と次ターンの通知で分かる（不完全、感染）。
外部委託では、業者が時期に適した術式で処置する。委託画面では術式を選ばず、委託費は時期に適した術式の費用とする。
【設計意図・非表示】選び間違いの可能性が、直接対応の「覚える・調べる」コストを実際のものにする。

術式ごとの違い：
・ゴムリング法：精索を締めて血流を止め、陰嚢以下を壊死・脱落させる。費用最小。
・去勢鉗子法：皮膚の上から精索を挫滅させる。陰嚢は残り、精巣は数か月かけて萎縮する。
  確実性がやや劣り、まれに去勢が不完全な個体が残る（付録C の失敗率）。
・観血法：陰嚢を切開し、精巣を摘出する。確実だが、資材費が高く感染リスクがある。
  直接対応では資格を持つ牧場主（プレイヤー）が処置する。獣医に頼む場合は外部委託と同じ扱い。
・旧来手法：焼烙法（Firing）。煮沸したナイフで陰嚢を切り裂き、手で精巣を引き抜く。鋭い切り口は出血が
  止まりにくいため、あえて荒い傷口にして収縮を促し、熱した鉄器（火箸）で傷口を焼く。
  設備や予算に余裕がなく、麻酔や十分なアニマルウェルフェアを実現できないときに行う。中世ヨーロッパから
  現在のアフリカまで広く行われており、処置として失敗しやすいわけではない。近代アニマルウェルフェア上の
  非推奨手法という位置づけ。
  ゲーム上の性質：設備の初期費用がかからず安い。代わりにストレス加算が大きく、しばらく回復しにくい。
  資材費がやや高い観血法を選べば、このデメリットは回避できる。
  （文章の本文は文章JSONで後から差し込む）

■ 直接対応と外部委託
直接対応：
・費用が安い。
・選んだ術式に応じた詳細な文章イベントが発生する（No.15）。
外部委託：
・委託費用を支払う。
・処置は背景で進み、帳簿に1行で記録されるだけで完了する。

【設計意図・非表示】直接対応は安いが、時期に合った術式を自分で判断し続ける記憶やメモの手間を
プレイヤーが負う。慣れると、本来重い選択を「安いから」「覚えたから」とクリックで日常的に
実行するようになり、それが重い処置を日常とする厩務員のロール体験になる。
外部委託はその手間を費用で置き換える選択肢の一つで、どちらも無理強いしない。
直接対応と委託の損得差を、この意図以外の理由で埋めたり広げたりしない。

■ ストレスと回復
去勢の身体的負担は、共通パラメータ「ストレス」への加算で処理する。
時期が遅いほどストレス増加と一時的な体重減少が大きい。
【虚弱体質】は悪影響を強める。ストレスはターン経過、好きな個体の存在、
任意のお世話で回復する。術後専用のパラメータは増やさない。

■ 行動の変化
・【気性難】による管理上の悪影響が軽減される（バッジ自体は変化しない）。
・母子関係、個体への好意はそのまま維持される。
・種牛・種牡馬として育てた個体も、途中から去勢して別用途に転換できる。

【仕様項目 No.15：去勢と繁殖の文章イベント】
==================================================

直接対応の去勢、人工授精、当て馬などでは、ノベルゲーム形式の文章イベントを表示する。
本作で最も重要な表現部分である。文章IDとダミー表示は付録A。

■ イベントの構成（去勢）
1. 見出し：日付、個体名、性別、月齢（1行）
2. 処置前の観察：その個体の様子
3. 機能の説明：生殖器官の構造と、そこで本来起こるはずだったこと
4. 処置の実施：選んだ術式の手順と、器官への作用
5. 反応：動物の身体的反応（性格・月齢・体質で差分）
6. 厩務員の主観：担当厩務員の短い独白（任意、0〜1行）
7. 直後：処置直後の様子
8. 帳簿：その処置の帳簿行（No.18 の形式で、文章イベントの末尾に表示）

術後の経過は、次のターン開始時に「経過日誌」として届く（付録A の course）。

■ 文章の本文
本文は別管理の文章データで後から差し込む。実装AIは去勢・繁殖・出荷の本文を書かない（No.00）。

■ 表示
・ノベルゲーム風のテキストウィンドウで、クリックで1段落ずつ進める。
・背景は普段の牧場画面をぼかしたもの。処置の画像は出さない。
・BGMは止めず、普段の牧場BGMを少し小さくする程度にする。

■ 既読スキップ
・既読の段落はスキップボタン（または長押し）で高速に通過する。
・未読の段落に来るとスキップが止まる。
・見出し行（個体名や日付を差し込んだ行）は、文章IDとしては既読なので止まらない。
・反応の段落は、条件ごとの有限の候補からランダムに選ぶ。全候補を読み終えると、
  そのイベントはスキップで最後まで止まらずに通過するようになる。
・既読率、読了数などの数値はどこにも表示しない。
・文章を読んだかどうかで、処置結果、数値、実績は変化しない。

【仕様項目 No.16：日常イベントと厩務員】
==================================================

NPC厩務員は2人。青服の男性（厩務員ボーイ）と赤服の女性（厩務員ガール）。
話し方と観察の仕方が異なる。事務所で名前を変えられ、担当する放牧地を選べる。

性格との相性：
・【おっとり】【甘えん坊】【活発】は厩務員ガールに適性。
・【好奇心旺盛】【マイペース】【頑固】は厩務員ボーイに適性。
・相性の良い個体には軽いバフ。「マイペースな子って可愛いですよね」などの台詞がある。

任意のお世話（放牧地や畜舎で個体を選んで行う）：
ブラッシング、ふれあい、運動。ストレス、幸福度、コンディション、当代能力、
なつき度が変化する。
お世話は1ターンあたりの回数に上限がある（付録C）。残り回数は数値だけで画面に表示する。
【設計意図・非表示】上限により「今季は誰に手をかけるか」が選択になり、マップを歩いて回る理由と
特定個体への愛着を生む。

日常イベント：
家畜の仕草、世話への反応、他個体との交流、厩務員の観察。
性格、なつき度、個体関係、担当厩務員で差分を設ける。
日常イベントは短く軽く、1〜3行で書く。

厩務員は家畜への愛着や戸惑いを持ち、ときには動物同士の関係を人間的に解釈する。
ただし、厩務員の解釈と、動物について確認できる事実は書き分ける。
厩務員の台詞は経営判断を批判しない。

【仕様項目 No.17：見下ろし2Dマップと施設操作】
==================================================

基本画面は親しみやすい見下ろし型2D牧場マップ。
主人公を方向入力で移動させ、施設に近づいて操作する。
施設のクリックや管理ウィンドウからの直接操作にも対応する。

主な施設・地点：
・事務所（管理ハブ）
・各施設へワープできる案内看板
・牛の放牧地・畜舎
・馬の放牧地・馬房（フェーズ3）
・搾乳施設、畑（フェーズ2）
・町への移動口（町はウィンドウ形式）

朝・昼・夜による所在管理はしない。労働施設に配置された個体にも放牧地で会える。

■ マップの広さとカメラ
・マップは画面より十分広いスクロール型にする（目安 2400×1800px）。
・カメラはプレイヤーに滑らかに追従する。
・画面の隅にミニマップを置き、牧場全体、放牧地、畑、建物、現在地、視界枠を表示する。
  ミニマップをクリック（タップ）すると、その地点へ移動できる。
・ダッシュ（Shiftキー、またはスマホ用のトグル）を用意する。
・案内看板は牧場の要所に複数置き、クリックで各施設へワープできる。
  マップが広いので、看板は実際に便利な移動手段として機能する。

■ 開拓前の土地
・未拡張の放牧地は「放牧地候補の丘」として描く。柵のないなだらかな丘、岩、野草、境界杭。
・未拡張の畑は「畑候補の荒れ地」として描く。乾いたひび割れ地、雑草、杭と看板。
・事務所または現地をクリックして拡張費用を払うと、その場所が変わる。
  丘は木柵と水飲み場のある放牧地に、荒れ地は畝の並んだ畑になる。
・拡張するほど、歩いて回れる牧場が広がっていく。

■ 家畜の移動範囲
・家畜は所属する放牧地の柵の内側から出ない。移動の目標座標と実際の座標を、
  その放牧地の境界内に必ず収める。
・プレイヤーはゲートから放牧地に出入りでき、中で家畜にふれあえる。

事務所でできること：
収支・資金・維持費・借入の確認、帳簿、個体一覧と詳細、個体アーカイブ、
繁殖計画・交配、去勢・出荷・売買、厩務員と放牧地の管理、施設の増設、
レース登録、重要通知と牧場の記録の確認。

飼育スロット：
牛と馬はそれぞれ飼育スロットを使う。仔畜、肥育中、繁殖用、引退個体、
労働配置中の個体もスロットを使い続ける。畜舎は放牧地の拡張に合わせて自動で増える。

町（ウィンドウ）：
家畜の売買、精液ストロー・外部種牡馬、処置委託。

経営管理のために毎回長距離を歩く必要がない操作性にする。

【仕様項目 No.18：帳簿・出荷画面・個体アーカイブ】
==================================================

■ 帳簿
事務所の帳簿には、すべての経営上の出来事を1〜3行で時系列に記録する。
帳簿は感情や描写を含まず、数値と経営用語だけで書く。

帳簿の行の例：
・去勢（ゴムリング・直接）　ゴロウ　資材費 ¥300　作業 10分
  　増体予測 −0.2kg/日（1ターン）　格付予測 脂肪交雑 ↑
・去勢（観血法・委託）　タロウ　委託費 ¥18,000
  　増体予測 −0.6kg/日（1ターン）※月齢による　格付予測 脂肪交雑 ↑
・人工授精　ハナコ　精液ストロー（肉質期待A）¥8,000　受胎
・人工授精　ハナコ　精液ストロー（肉質期待A）¥8,000　不受胎　空胎 +1ターン　飼料費 ¥63,000
・出荷　個体識別番号 1234567890　枝肉 452kg　肉量 A　肉質 A　売上 ¥1,280,000

■ 出荷画面
出荷を確定すると、次の順で表示する。
1. 個体の立ち絵と名前（普段の個体詳細と同じ）
2. 短い出荷の文章（厩務員の見送りの一言、またはトラックが出ていく1〜2行）
3. 画面が切り替わり、商品ラベルの形式で表示する：
   部位の見出し、枝肉重量、格付（肉量・肉質）、売上金額、個体識別番号
   このラベルには名前、性格、関係値を表示しない。
4. 帳簿に1行追加され、所持金が増える演出（No.19）

■ 格付
格付は現実の表記（A4など）を使わず、バッジと同じアルファベットのランクで「肉量」と「肉質」の2項目を表示する。
・肉量：【深み/肉付き】のランクで決める（例：【深み/肉付きA】の牛 → 肉量 A）。
・肉質：遺伝の【肉質】を基礎に、去勢時期・肥育・年齢・未去勢の補正を加えた出荷時の評価で決める
  （例：【肉質A】で補正なしの牛 → 肉質 A）。
・ランクは 平凡、C、B、A、A+、S。平凡＝特筆する数値を持たない。C＝その分野で特筆する数値を持ち始め、
  個性として遺伝可能になる。
・内部数値（平凡0、C1、B2、A3、A+4、S5）は計算用で、画面には出さない。
・枝肉単価は肉質のランク（付録C）で決める。

■ 個体アーカイブ
出荷・死亡・売却した個体は、事務所の個体アーカイブに残る。
・名前、個体識別番号、生年、去勢の時期と術式、出荷日、売上を表示する。
・その個体の過去の日誌（文章イベント）を読み返せる。
・アーカイブを見るよう促す通知や台詞は出さない。

【仕様項目 No.19：かわいい手触り】
==================================================

【設計意図・非表示】本作は「かわいい牧場ゲームとして本当に楽しい」ことが前提になる。
かわいさと心地よさが弱いと、文章との落差が生まれず、作品が成立しない。
次の手触りを必ず実装する。

・家畜が放牧地を歩き回り、ときどき止まって草を食べ、絵文字の吹き出し
  （♪、💤、❤、💢）を出す。
・お世話をすると、ハートやキラキラのエフェクトと効果音。
・収入時に「+¥」の数字が跳ねて所持金に吸い込まれる演出。
・季節の切り替えで、背景の色と花・雪などの演出が変わる。
・出産時は明るいファンファーレと「新しい家族が生まれました！」の通知。
・通知、ボタン、ウィンドウは丸みのあるパステル調で統一する。
・個体の立ち絵は、性格によって表情が少し違う。

これらの演出は、去勢・出荷の前後でも一切変えない。
去勢判断期の通知も、出荷時の所持金の演出も、他と同じように明るく行う。

【仕様項目 No.21：フレーバーテキストJSONと開発者モード】

ゲーム内の文章は外部JSONから読み込み、処理と文章を分離する。

■ JSONで管理する文章
個体の性格・行動・仕草、個体関係の説明、厩務員の台詞と日常イベント、
お世話への反応、繁殖・交配・出産、去勢（術式、機能、反応、経過）、出荷の文章。

■ 形式
{
  "文章ID": {
    "text": "本文。{name} などのプレースホルダーを含められる。",
    "speaker": "narration | staff_girl | staff_boy | animal",
    "cond": { "species": "cattle", "method": "ring", "personality": ["おっとり"] }
  }
}
・cond は省略可能。条件判定はJS側が行い、JSONは本文と付帯情報だけを持つ。
・同じ条件に複数の候補がある場合、IDの末尾を _01, _02… とし、JSがランダムに選ぶ。
・長いイベントは複数のIDを順に表示する（イベント定義はJS側に持つ）。
・プレースホルダー：{name} {sex} {age} {species} {staff} {partner} {date} {id_number}

■ ファイル構成（例）
animals.json、daily-events.json、breeding.json、castration.json、economy.json
ファイル間で文章IDを重複させない。

■ ローカル読み込み
file:// で開いた場合もJSONを使えるように、JSONを読み込むJSファイル
（例：window.TEXT_DATA = {...}）としても同梱する。ゲーム内から文章JSONを読み込んで
差し替える機能も設ける。

■ 既読管理
文章IDごとに既読を管理し、セーブデータに保存する。
本文を編集しても、IDが同じなら既読状態を維持する。

■ 開発者モード
表示中の文章のIDを表示し、コピーできるようにする。
複数の文章を組み合わせている場合は、それぞれのIDを表示する。


==================================================
【付録A：文章イベントの文章IDとダミー表示】
==================================================
文章イベントの本文は、この仕様書には含めない。ゲーム完成後に、別管理の文章データで
JSONの本文を差し替える。実装AIは、以下の文章IDを持つダミーJSONを作り、
イベントの流れ・分岐・既読スキップがすべて動く状態にする。

■ ダミー本文の形式
各IDの text には、IDと役割だけを書く。
例："cas.ring.act": { "text": "［cas.ring.act｜処置の実施］", "speaker": "narration", "cond": { "method": "ring" } }
プレースホルダーの動作確認のため、見出しだけは差し込みを入れる。
例："cas.head": { "text": "［cas.head］{date}｜{name}　{species} {sex}　生後{age}", "speaker": "narration" }

■ 去勢（castration.json）
cas.head　見出し
cas.ring.pre_01, cas.ring.pre_02（性格差分）　処置前の観察
cas.ring.tool　器具の準備
cas.ring.locate　対象の確認
cas.cattle.function_sperm　機能の説明1
cas.cattle.function_hormone　機能の説明2
cas.ring.act　処置の実施
cas.ring.react_01〜03（性格差分）　反応
cas.react_projection_01　語り手の一文（50%で表示）
cas.staff_girl_01 / cas.staff_boy_01　厩務員の主観（30%で表示）
cas.ring.after　直後
cas.ring.course_01　次ターンの経過日誌
cas.burdizzo.act, cas.burdizzo.course_01　去勢鉗子法
cas.surgical.act　観血法
cas.<method>.mismatch_01　適さない時期に行った場合の差し替え段落（処置の実施の直後に挿入）
（馬、他の術式・時期は同じ構成で cas.<method>.<段階> を追加する）

■ 去勢イベントの表示順（ゴムリング法）
cas.head → cas.ring.pre_*（ランダム）→ cas.ring.tool → cas.ring.locate
→ cas.cattle.function_sperm → cas.cattle.function_hormone → cas.ring.act
→ cas.ring.react_*（ランダム）→ cas.react_projection_*（50%）
→ 担当厩務員の cas.staff_*（30%）→ cas.ring.after → 帳簿行

■ 繁殖（breeding.json）

breed.teaser.act_01, breed.teaser.after_01（馬・当て馬）

■ 獣医アドバイス（economy.json）
vet.advice.early, vet.advice.standard, vet.advice.late, vet.advice.mature　時期ごとのアドバイス
vet.advice.ring, vet.advice.burdizzo, vet.advice.surgical　術式ごとのアドバイス

■ 出荷（economy.json）
ship.farewell_01, ship.farewell_02, ship.buyer_marbling_01（肉質 A+以上）

cond に使うキー：species, method, personality, partner_in_pasture, meat_grade_min
